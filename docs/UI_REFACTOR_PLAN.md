# 表情管家 UI 重构实施方案

- 文档状态：界面、审核修复与参考图视觉调整已实施；平台真机验收待完成
- 创建日期：2026-09-16
- 更新日期：2026-09-17
- 设计依据：本次确认的桌面版效果图
- 适用范围：Windows、macOS 主管理窗口，以及快速选择窗口和 Android 的适配

## 1. 重构目标

主管理窗口采用左侧分组导航、顶部搜索与操作、内容标题与数量、主体表情网格的布局。界面以白色和浅灰色为主，青绿色用于主操作、选中和键盘焦点。

表情图片是主要内容，因此界面保留参考图的布局与配色，并按照后续反馈缩小文字、控件和卡片。实际列数根据可用宽度与缩略图密度计算，标准密度下 1100 宽窗口显示五列，1536 宽窗口显示七列。界面展示用户实际的表情库，效果图中的素材、分组和数量仅用于视觉参考。

重构继续使用现有数据仓库、导入服务和平台桥。数据库 schema 与迁移包格式无需因本次界面调整而变化。

## 3. 组件职责

新增界面组件统一位于 `lib/ui/`。沿用现有状态管理方式，组件通过数据和回调调用业务操作。

| 组件 | 职责 |
| --- | --- |
| `AppTheme` | 定义颜色、字体、间距、圆角及控件样式 |
| `LibraryPage` | 协调加载、分组、搜索、排序、选择状态和业务动作 |
| `LibrarySidebar` | 展示分组、数量、新建分组及设置入口 |
| `LibraryToolbar` | 展示搜索、导入、多选和更多操作；多选时展示批量操作 |
| `StickerGrid` | 展示表情网格，处理滚动、框选和键盘定位 |
| `GridMetrics` | 统一提供列数、卡片尺寸、间距和卡片位置 |
| `StickerCard` | 展示图片、名称、悬停操作和卡片状态 |
| `LibraryFeedback` | 展示操作结果和独立的进度状态 |

现有导入、备注、分组和设置对话框按职责逐步迁移。`main.dart` 保留初始化与应用启动。`StickerRepository` 和 `ImportSource` 继续作为业务边界，平台能力通过平台桥调用。

## 4. 视觉规范

尺寸均使用逻辑像素，实际布局按窗口约束调整。

| 项目 | 建议值 |
| --- | --- |
| 主背景 | `#F6F8FA` |
| 侧栏背景 | `#EAF0F4` |
| 卡片背景 | `#FFFFFF` |
| 搜索框 / 导航选中背景 | `#EEF2F6` / `#D6ECEE` |
| 强调色 | `#008B8B` |
| 边框 | `#DFE6ED` |
| 主文字 | `#101828` |
| 辅助文字 | `#788698` |
| 侧栏宽度 | 240 |
| 桌面搜索框与主按钮高度 | 48 |
| 排序与密度控件高度 | 40 |
| 按钮圆角 / 卡片圆角 | 10 / 12 |
| 内容边距 / 网格间距 | 标准 20 / 14，紧凑 18 / 10 |
| 应用名 / 内容标题字号 | 22 / 24 |
| 侧栏文字 / 卡片备注字号 | 18 / 15 |
| 工具栏文字 / 数量字号 | 16 / 14；窄布局工具栏为 15 |

侧栏使用青绿色猫咪轮廓标识与浅青色选中背景。搜索框采用浅灰蓝色底色，排序与密度控件位于内容标题行右侧；空间不足时，控件在下一行右对齐。卡片主要通过底色与细边框区分，悬停时显示浅青色边框与复制按钮。名称使用单行省略，悬停显示完整备注。

窗口标题栏沿用系统控件，因此 Windows 和 macOS 分别显示自身的窗口按钮。

## 5. 布局与操作入口

### 5.1 窗口适配

| 场景 | 布局 |
| --- | --- |
| 主管理窗口宽度 ≥ 1,000 | 固定侧栏，搜索与常用操作同行，右侧展示自适应网格 |
| 主管理窗口宽度 720–999 | 分组通过可展开导航呈现，优先保证搜索与网格空间 |
| 快速选择模式 | 沿用约 `760×600` 的紧凑窗口，以搜索、分组切换和高密度网格为主 |
| Android | 使用触摸尺寸和移动端导航，保留分享导入、悬浮面板和 GIF 长按预览 |

快速选择模式由窗口模式决定，不能仅凭窗口宽度判断。主管理窗口缩小时仍应保留管理能力。

### 5.2 操作位置

| 位置 | 操作 |
| --- | --- |
| 侧栏顶部 | 应用标识和名称 |
| 侧栏主体 | 全部表情、现有分组、分组数量、新建分组 |
| 侧栏底部 | 设置入口，使用现有快捷键及平台相关设置对话框 |
| 顶部工具栏 | 搜索、多选、导入表情、更多 |
| 更多菜单 | 快速唤出、加密迁移包导入导出、清理导入记录 |
| 内容标题行 | 当前分组、表情或搜索结果数量、排序、缩略图密度 |
| 多选工具栏 | 选择数量、全选当前列表、移动、删除、退出多选 |

删除和清理继续使用现有确认流程。新布局需要覆盖每个已有操作，避免因菜单调整而失去功能入口。

## 6. 卡片与网格交互

### 6.1 状态表达

| 状态 | 表现 |
| --- | --- |
| 默认 | 白底、细灰边框 |
| 悬停 | 轻微强调边框，显示复制按钮 |
| 多选 | 显示勾选框；选中时使用青绿色边框与勾选标记 |
| 键盘焦点 | 网格实际拥有主焦点时显示青绿色轮廓；已多选卡片使用独立深色轮廓 |
| 复制或发送成功 | 显示短暂反馈，不改变多选状态 |

图片继续按原比例完整展示，保留缩略图失败回退、图片错误占位和 GIF 悬停播放。快速选择模式继续使用适合高密度浏览的卡片。

Android 卡片底部显示备注和“表情操作”菜单，菜单提供管理分组、编辑备注与删除表情；置顶按钮位于图片右上角。操作入口使用菜单后，窄卡片无需同时容纳三个按钮，因此可保留备注空间与正常的触摸区域。

卡片的展示分支依据主题中的目标平台选择，因此测试可以在 macOS、Windows 或 Linux 上明确指定 Android 布局。原生复制、发送等平台能力仍由原有平台桥处理。

### 6.2 使用与复制

卡片单击执行现有平台使用动作。右上角复制按钮仅写入剪贴板，不触发窗口激活、自动粘贴或回车。

独立复制通过 `PlatformBridge` 提供明确入口，并复用现有剪贴板实现。Windows 的复制与发送共用现有互斥机制，避免复制在发送期间覆盖剪贴板。使用计数继续遵守平台规则：Windows 仅复制不计使用次数，macOS 与 Android 成功复制计入使用次数。

复制按钮点击不得继续触发卡片使用动作。卡片双击去重、选择模式切换时取消待执行点击、框选结束后的误点击抑制需要继续有效。

### 6.3 网格计算

`GridMetrics` 根据网格实际可用宽度、密度、内边距和间距统一计算布局。主管理窗口的卡片高度为实际卡片宽度加 32，因此窗口缩放时图片区域维持接近正方形的比例。快速选择窗口保留原有紧凑高度。网格渲染、框选命中、空白区域判断和键盘滚动共同使用这些结果。

窗口缩放、密度切换或排序变化后，焦点应尽量保留在同一张表情上。若该表情已不在当前结果中，则将焦点移至有效结果或清空。

搜索框获得输入焦点时，方向键与回车优先服务于输入操作。网格获得焦点时，方向键负责导航，回车执行使用或选择动作。

## 7. 数据展示与反馈

### 7.1 分组与数量

分组数量根据已加载的表情及分组关系计算，无需新增数据库计数字段。导入、删除和分组修改成功后更新数量。

侧栏显示各分组总量，内容标题显示当前列表数量；搜索时显示搜索结果数量。表情与分组为多对多关系，因此各分组数量之和可能大于全库数量。

“全部表情”作为界面展示名称，继续使用现有 `all` 分组标识。

### 7.2 排序与密度

排序下拉框显示实际排序规则。普通分组和 QQ 收藏保留现有默认规则，并增加“最近导入”选项；用户选择后按导入时间排序。排序逻辑统一由 `UsageRankingService` 提供，组件不自行实现另一套排序。

缩略图密度提供紧凑、标准两档，通过 `AppPreferences` 保存用户选择。密度调整后的尺寸变化统一交给 `GridMetrics`。

### 7.3 搜索

搜索提示使用“搜索备注或表情 ID”，沿用当前分组内搜索、忽略大小写和去除首尾空格的规则。

目前导入文件名保存在初始备注中，编辑备注后不再具备独立的原始文件名检索能力，因此本次文案与现有字段保持一致。

### 7.4 操作反馈

成功提示使用内容区底部的小型浮层，依据实际结果显示“已复制”或“已发送”。失败提示展示具体原因；已粘贴但回车失败等部分完成状态继续保留准确说明。

导入进度独立展示，并避免与操作结果提示重叠。没有表情、当前分组为空、搜索无结果和初始化失败使用相应状态，提供导入、清除搜索或重试等适用操作。

## 8. 实施阶段与完成标准

| 阶段 | 工作内容 | 完成标准 |
| --- | --- | --- |
| 1. 拆分界面职责 | 迁移主题、页面、展示组件及对话框，明确状态和回调 | 原有操作可用，展示组件可独立验证 |

| 4. 实现数据展示与反馈 | 实现计数、排序选项、密度偏好及小型反馈提示 | 控件与真实数据一致，各状态可正确展示 |
| 5. 跨平台验收 | 执行测试、截图对比、平台操作验证并更新文档 | 主要窗口状态、平台交互和既有检查通过 |

界面实现与本次审核发现的问题已完成代码调整，对应自动化验证记录见 `CHANGELOG.md`。平台真机交互和完整视觉验收仍需按第 9 节执行，因此当前状态不代表全部平台已经验收。

## 9. 验证方案

### 9.1 自动化测试

- 分组切换、搜索、结果数量和多对多分组计数正确。
- 普通分组与 QQ 收藏的默认排序保持正确，最近导入选项实际改变顺序。
- 不同窗口宽度和密度下，框选与键盘定位命中正确卡片。
- 复制按钮只执行一次复制，不触发卡片使用动作。
- 多选、拖拽结束和模式切换不会产生延迟发送。
- 搜索输入与网格键盘导航的焦点行为正确。
- 新增密度偏好能够保存、恢复并具有有效默认值。

### 9.2 视觉与交互验收

使用相同测试数据对比以下窗口尺寸，单位为逻辑像素：

| 场景 | 尺寸 |
| --- | --- |
| 宽主管理窗口 | `1440×900` |
| 默认主管理窗口 | `1100×760` |
| 最小主管理窗口 | `720×520` |
| 快速选择窗口 | `760×600` |

检查默认列表、长备注、空分组、搜索无结果、导入中、多选及失败提示。确认控件无溢出，窗口变窄后主要操作仍可访问，图片不被拉伸或裁切。

Windows 验证托盘、快速唤出、复制与自动发送；macOS 验证菜单栏、快捷键及图片和 GIF 复制；Android 验证分享导入、长按预览和悬浮面板。

### 9.3 项目检查

实施阶段从仓库根目录执行：

```sh
dart format lib test
flutter analyze
flutter test
node tool/verify_project.mjs
```

现有 `tool/verify_project.mjs` 会检查 `main.dart` 内是否存在文件选择代码。文件选择逻辑迁移后，需要同步调整该检查，使其对应实际职责位置。

平台构建通过现有 Windows、macOS、Android CI 验证；真实剪贴板、窗口焦点和系统分享行为需要在对应平台进行交互验收。
