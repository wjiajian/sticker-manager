# 架构与产品决策记录

本文件记录影响用户行为、数据兼容性或平台能力的决定。新决定追加编号，不修改历史结论；若结论被替代，注明替代关系。

## ADR-001：Flutter 作为共享 UI 与业务层

**日期：** 2026-09-13  **状态：** 已采纳

Windows 和 Android 共用 Flutter 页面、模型、SQLite 服务和导入/排序逻辑；平台差异集中在 runner、Android Activity/Service 和桥接类中。这样可以保持行为一致，同时允许使用原生剪贴板、托盘、热键和悬浮窗。

## ADR-002：本地优先，内容哈希去重

**状态：** 已采纳

媒体和 SQLite 存在应用私有目录，不上传服务器。SHA-256 是跨设备迁移和重复导入的稳定身份；重复媒体不新增记录，但会补充本次选择的分组关系。删除只处理应用副本。

## ADR-003：QQNT 只从明确的个人表情目录探测

**状态：** 已采纳

QQNT 的自动探测路径是 `Tencent Files\<纯数字QQ号>\nt_qq\nt_data\Emoji\personal_emoji\Ori`。`marketface` 和 `emoji-recv` 只作为明确标记的候选，不把账号根目录或 QQ 安装根目录递归扫描。历史上尝试过的 `D:\QQ\_NT\dialogue\Tencent Files` 直接根路径已排除；便携安装只检查已知布局（如 `QQ_NT\dialogue\Tencent Files`）下的数字账号目录。

原因是群聊记录、接收表情和缓存通常与账号目录共存；限定目录并让用户在预览阶段逐文件确认，才能降低误导入风险。每个明确目录最多扫描 1,000 个文件，兼容普通用户约 500 和 SVIP 约 1,000 的收藏上限。

## ADR-004：QQ 收藏保留源顺序

**状态：** 已采纳

导入 QQ 时记录扫描顺序 `sourceOrder` 并自动加入 `QQ收藏`。该分组按 `sourceOrder` 升序展示，不套用使用频率排序，以便用户看到与 QQ 收藏界面一致的顺序；没有顺序的记录排在末尾。

## ADR-005：Java 17 构建约束

**状态：** 已采纳

本项目当前验证环境使用 JDK 17，Android/Kotlin 字节码目标也为 Java 17，最低 Android API 为 28。Java 21 在 Gradle 兼容时可以作为运行时，但不是本机验证基线；Java 11 不满足当前 Gradle/Android Gradle Plugin，不能作为 `JAVA_HOME`。后续若升级构建链，需重新验证并更新本记录。

## ADR-006：Windows 单实例与托盘生命周期

**状态：** 已采纳

runner 使用命名互斥体和就绪事件保证只有一个项目进程。重复启动激活已有窗口后退出；窗口关闭隐藏到托盘；托盘“退出”才执行完整清理并终止进程。此策略解决热键重复注册、托盘图标残留和多个数据库连接的问题。

## ADR-007：一次性目标窗口与发送语义

**状态：** 已采纳

热键打开前捕获外部顶层窗口，目标句柄只用于当前一次发送，成功或失败后清除。托盘图标左键/双击打开完整主管理窗口时捕获当前或 5 秒内的最近外部窗口，允许完整窗口卡片单击发送；右键菜单的“打开表情管家”不会从 Z 序猜测目标并清除一次性句柄。主管理界面的“快速唤出”按钮也可以明确请求复用最近外部窗口，但只接受 5 秒内仍有效的原生快照，并在消费后冻结为一次性目标。没有有效目标时只复制剪贴板，不使用过期句柄，也不把仅复制计入 Windows 使用次数。单击在快速模式固定执行粘贴并回车；托盘双击事件合并为一次操作。发送失败不增加使用次数，粘贴成功但回车失败会报告“已粘贴”并保留准确状态。

## ADR-008：托盘右键是显式上下文菜单

**状态：** 已采纳

`tray_manager` 在 Windows 右键只回调 `onTrayIconRightMouseDown`，不会自动弹出菜单，因此回调必须调用 `trayManager.popUpContextMenu()`。菜单仅包含“打开表情管家”和“退出”；左键继续打开窗口。

## ADR-009：Windows 卡片管理动作集中到右键

**状态：** 已采纳

卡片单击保留复制/发送这一高频动作；置顶、编辑备注、管理分组和删除集中到右键菜单，避免卡片底部按钮占用网格高度。删除继续二次确认。Android 长按 GIF 预览不受此 Windows 菜单决策影响。

## ADR-010：搜索字段和范围

**状态：** 已采纳

搜索先限定当前分组，“全部”代表全库；匹配用户备注、导入时的原始文件名备注和表情 ID，去除首尾空格且不区分大小写。继续使用现有 `note` 字段，不增加数据库列，降低迁移成本。

## ADR-011：快速选择窗口尺寸与模式

**状态：** 已采纳

区分主管理模式和快速选择模式。快速模式默认 `760×600`，目标卡片约 `112×132`，隐藏冗余管理按钮；标题栏允许最大化、还原和关闭。主管理模式保存最近窗口尺寸和最大化状态，模式切换不改变剪贴板、目标捕获和使用计数。

## ADR-012：框选遵循桌面常见语义

**状态：** 已采纳

框选只在多选模式启用。普通拖拽替换选择，按住 `Ctrl` 追加；Windows 多选时锁定列表拖动并用鼠标滚轮浏览，避免滚动手势抢占框选。`Esc`、顶部 `X` 或网格空白右键清空并退出。下一次无 Ctrl 拖拽直接覆盖误选。拖拽结束不触发卡片延迟单击，防止误发送。

## ADR-013：Android 长按保留预览

**状态：** 已采纳

Android 端长按 GIF 用于预览动画，不复用 Windows 右键管理菜单。管理操作继续通过现有 Android 控件和主界面完成，避免改变已验证的分享/悬浮面板手势。

## ADR-014：迁移包使用认证加密并版本化

**状态：** 已采纳

迁移包是带 `formatVersion` 的 ZIP，密码派生 AES-256-GCM 密钥，manifest 与媒体一起认证加密。导入校验魔数、密码、ZIP、版本和每个媒体 SHA-256；不支持版本或篡改包不得写入数据库。云端同步不属于此格式的职责。

## ADR-015：文档随行为和格式变更同步

**状态：** 已采纳

任何影响用户交互、数据库字段、导入路径、平台桥接或迁移格式的改动，都要更新 `PROJECT_SPEC.md`、`ARCHITECTURE.md`、本文件和 `CHANGELOG.md`，并在测试记录中说明验证范围。这样可以保留问题修复的原因和兼容边界，减少后续维护时依赖口头上下文。

## ADR-016：便携 QQ 路径采用有限相对探测

**状态：** 已采纳

除了用户文档和应用数据目录，Windows 自动导入会在各盘符的 `QQ` 目录下只检查一层子目录及其 `dialogue/Tencent Files` 子路径，再进入纯数字账号目录。不会固定使用某个盘符、QQ 版本号或安装绝对路径，也不会递归扫描 QQ 安装目录；个人表情仍只取 `personal_emoji/Ori`，收到和市场目录默认取消选择。

## ADR-017：发送目标以 WM_HOTKEY 快照为准

**日期：** 2026-09-13  **状态：** 已采纳

### 背景

热键事件经过插件调度后才执行 Dart 回调，回调时前台窗口可能已经变成表情管家。QQNT 的输入子窗口也可能在快速面板打开期间销毁并创建新的 HWND；继续使用旧句柄会导致激活失败，或因句柄复用把内容送到错误窗口。

### 决定

- runner 在 `WM_HOTKEY` 消息阶段先保存一次 pending 外部 HWND 和时间戳；Dart 快速唤起回调只消费这份短时快照。
- 快速发送目标冻结进程 PID、窗口类名和标题，之后的前台事件不得覆盖冻结字段。
- 若 HWND 失效，只在冻结 PID 内枚举可见顶层窗口，先要求类名和标题精确匹配；标题变化时仅在同类窗口唯一的情况下按原 PID 重解析。即使 HWND 数值仍有效，也要校验冻结类名；禁止在多个 QQNT 窗口中任意挑选，也禁止跨进程猜测。
- 激活阶段最多短暂重试，并验证实际顶层前台句柄确实等于解析结果；验证失败时不注入 `SendInput`。
- 托盘图标左键/双击打开主管理完整窗口时捕获当前或 5 秒内的最近外部快照，忽略任务栏和桌面壳窗口，允许完整窗口卡片单击完成一次发送；双击事件在 800ms 内合并。右键菜单的“打开表情管家”清除 pending/one-shot 目标；快速唤出按钮同样只可消费 5 秒内的最近外部快照，过期或没有目标时单击只复制。

### 取舍与后果

该策略增加 runner 的状态和短暂重试，但把热键竞态、PID 边界和前台条件固定在原生层。窗口标题变化时，如果同类窗口唯一仍可恢复；存在多个候选时宁可报告发送失败，也不把内容发送到不确定的窗口。`clearExternalWindowTarget` 带 expected HWND，旧异步清理不会擦掉更新后的新快照。

## ADR-018：托盘按下时原生捕获并串行发送

**日期：** 2026-09-13  **状态：** 已采纳

托盘图标消息由 `tray_manager` 转发到 Flutter 顶层窗口。Windows runner 在 `WM_USER + 1` 的左键按下阶段先保存外部前台快照，左键抬起只作兜底；同一 800ms 窗口内的第二次消息不会覆盖首个快照。这样双击托盘进入主管理完整窗口时，目标捕获不会等待 Dart 回调，也不会被任务栏或表情管家自身抢占。

Windows 写剪贴板、激活目标、注入 `Ctrl+V`/`Enter` 的完整流程通过异步互斥串行执行。旧异步捕获结果只依据代次在 Dart 侧丢弃，不使用不带代次的 HWND 清理去擦除新快照；没有有效目标时仍只复制，不发送。

## ADR-019：导入和迁移包采用有限资源预算

**日期：** 2026-09-15  **状态：** 已采纳

单个图片或 GIF 文件最多读取 `64 MiB`，单次导入最多预留 `512 MiB` 源文件；超过限制的文件在准备阶段跳过并在结果中说明。Android 分享导入使用同样的单文件限制和批次总量限制，复制未知大小的 `content://` URI 时由有界流再次检查。迁移包解密前最多接受 `768 MiB` 密文，认证解密后的明文最多 `512 MiB`。

这些上限用于限制损坏文件、异常 URI 或恶意迁移包造成的内存、磁盘和后台任务占用，不改变 QQ 普通用户 500 个或 SVIP 1,000 个表情的正常导入能力。超限项不会删除源文件，也不会写入数据库；已成功提交的项目仍保留。

## ADR-020：重复启动恢复主管理模式

**日期：** 2026-09-15  **状态：** 已采纳

Windows 使用单实例互斥体。后续启动只激活已有窗口，并通过 `WM_APP + 17` 通知 Flutter 离开快速选择模式、恢复主管理模式和保存的窗口状态；不会创建第二个托盘、热键或数据库实例。托盘右键的“打开表情管家”仍清除一次性发送目标，避免把管理入口误当成发送入口。

## ADR-021：Windows 便携包提供明确启动入口

**日期：** 2026-09-16  **状态：** 已采纳

Windows ZIP 采用便携分发，不强制安装程序或管理员权限。为让首次使用者能在解压目录中快速找到入口，ZIP 根目录必须包含 `README_FIRST.txt` 和 `Start-StickerManager.cmd`；启动脚本只调用同目录的 `sticker_manager.exe`，不执行安装、联网或修改系统设置。直接双击可执行文件仍然受支持。

## ADR-022：macOS 采用原生剪贴板与共享桌面交互

**日期：** 2026-09-16  **状态：** 已采纳

macOS 工程使用 Flutter 3.47.3 官方模板，最低系统版本为 12。`QuickPickerController` 复用窗口管理、菜单栏图标和全局快捷键，默认组合为 `Cmd+Shift+E`。Windows 的目标窗口捕获和按键注入仍限定在 Windows，macOS 成功复制计为一次使用，由用户切换目标应用并粘贴，因此不需要辅助功能授权。

`MainFlutterWindow` 通过 `sticker_manager/platform` 实现 `copySticker`。静态图片转换为 PNG；GIF 同时写入原始数据和文件 URL，以保留动画。文件选择后立即复制到应用管理目录；Debug 和 Release 均允许沙箱内访问用户选择的文件。数据库 schema 和迁移包格式不变。

Actions 分别验证并构建 Windows、macOS 和 Android。macOS 使用 `ditto` 创建保留应用包结构的 ZIP，CI 产物用于测试。公开分发所需的 Developer ID 签名、公证和 Android 正式签名由发布环境另行配置。

## ADR-023：网格焦点与独立复制保留明确的操作边界

**日期：** 2026-09-17  **状态：** 已采纳

主管理窗口增加搜索、排序和悬停复制后，页面级键盘监听会使输入框的回车触发表情使用。因此键盘事件仅由网格范围处理，且要求网格自身拥有焦点；排序与数据刷新按表情 ID 恢复焦点，避免索引变化后操作另一张图片。布局、框选和键盘定位共用 `GridMetrics`。

卡片单击保留平台使用动作，独立复制按钮仅写入剪贴板。Windows 两种动作共用互斥锁，从而保留原有自动发送能力，同时避免独立复制在发送过程中覆盖剪贴板。此决定扩展 ADR-009 的卡片操作入口，并保持 ADR-018 的串行发送约束。
