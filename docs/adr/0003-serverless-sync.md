# 不自建服务器，在客户端合并同步

同步只依赖用户自己提供的存储后端（WebDAV、S3 兼容存储、本地同步文件夹）。这些后端只能存取文件、不能执行逻辑，所以合并全部在客户端完成：

- 原图按分类目录和表情名称存放，目录树决定分类与文件名，手动修改也能被应用识别；
- 元数据（分类、收藏、配文、使用记录）由每台设备追加写自己的操作日志，其他设备拉取后，按固定规则合并。

不自建服务器，是为了避免运维和费用，也让数据完全留在用户自己的存储里。代价是没有实时推送，只能靠定时拉取。

## 合并规则

- 文件移动和改名先拉取，远端路径相对上次观察发生变化时以远端为准；同一个表情的删除、改配文、改收藏按较晚的字段修改合并；不同字段、不同表情的改动互不影响。字段时钟、分类、去重和日志格式见 [ADR 0005](0005-sync-format-and-merge.md)。
- 使用次数：每台设备各自计数，合并时相加；最近一次使用时间取各设备中最晚的。
- 删除：见 ADR 0004。

照这套规则，同步永远不需要人工处理冲突，所以界面里不做冲突处理。

## 后果

- 第一版不做端到端加密，存储后端能看到原图。以后可以加成一个可选开关，代价是每台设备都要输入同一个密码。
- 每次使用都会产生一条要同步的记录，所以推送要攒批：本地改动后等 10 秒没有新改动，再一起推送。
