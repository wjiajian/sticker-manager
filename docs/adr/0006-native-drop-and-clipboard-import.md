# 原生拖入与剪贴板导入共用暂存和导入链路

## 背景

聊天软件可能不提供本地文件路径，而是提供 GIF、WebP、PNG、JPEG、TIFF、Windows DIB 或文件承诺。现有的文件路径拖入还承担拖表情到分类的功能，不能整体替换。剪贴板也可能只有 HTML 或网络图片地址。

## 决策

- macOS 在运行时替换 `WryWebView` 类的六个拖放方法，按实例登记主窗口和悬浮球。`wry` 使用 `objc2::define_class!` 默认命名时会注册带模块与版本后缀的类名（例如 `wry::wkwebview::class::wry_web_view::WryWebView0.57.1`），查找类时沿继承链同时匹配旧式 `WryWebView` 与带版本的 `wry::...::WryWebView<version>`，兼顾 KVO 动态子类且不改实例的 isa。未登记的窗口和有效文件路径仍走 Wry 原实现；仅原生图片或文件承诺走新链路。替换前核对方法签名，缺失的 prepare/conclude 有安全默认值。
- 升级 Tauri/Wry 时必须复核 `macos_drop.rs`：内部类名、继承链、方法签名、注册拖入类型、原有文件路径收集和事件行为。不能把 Wry 内部类名当作稳定公共 API。
- Windows 主窗口和悬浮球接收 OLE 图片、虚拟文件与本地路径，面板仍只处理原文件路径事件。后台工作线程保留 COM 生命周期。
- 原生字节和文件承诺先进入临时目录，统一使用 core 导入。保留动图原始字节，TIFF/DIB 转 PNG，限制临时数据项数和大小。直接传入文件不因暂存子目录而产生分类。真实文件路径沿用原导入行为。
- 剪贴板仅在后端按格式读取，不注册全局粘贴快捷键，不改变原生编辑菜单。HTML 仅是剪贴板的兜底来源，不参与拖入资格判断。

## 边界与取舍

导入不主动请求网络图片地址；HTML 只识别本地文件 URL 和指定格式的 base64 图片。拒绝含远程主机的文件 URL、UNC/SMB，不从远程地址下载图片（避免泄漏本机网络身份）。不解析 WebArchive，不从剪贴板接收 macOS 文件承诺。来源只允许内部拖动或未提供可读图片时，无法恢复原始文件，应提示先保存图片。

替换 Wry 内部方法比关闭 Tauri 拖放再重建所有路径事件更小，但增加了升级复核和真实窗口测试成本。
