# 同步格式 2：目录树决定分类与原图，日志合并其余状态

用户可以直接在 R2、WebDAV 或同步文件夹里建目录、放图、改名、移动和删除。远端目录树因此是文件路径的真相；不可变日志保留表情身份、字段时钟、分类颜色与排序、使用记录和永久删除标记。缩略图仍由每台设备生成，不上传。

## 布局与名称

```text
<根>/
  收到.png                              未分类
  工作/收到.png                         分类「工作」
  工作/收到 (2).png                     同分类内同名、内容不同
  .sticker-manager/
    library.json                        {"format":2,"id":"<uuid>","createdAt":毫秒}
    devices/<设备 id>.json
    ops/<设备 id>/<首 seq>-<末 seq>.jsonl
    trash/<表情 id>.<扩展名>
```

远端不再读写 `objects/`。本机仓库仍按内容哈希保存原图，这是本机布局，不是同步格式。读取根目录和 `未分类/` 下的图片都算未分类，应用写入统一使用根目录。分类只有一层；更深路径不导入。新出现的空目录也可以建立分类，目录变空不自动删除本机分类。

文件名由表情名称加原图扩展名组成；分配新路径时，用 Rust `to_lowercase()` 判断占用，不做 Unicode 规范化；同分类内不同内容重名（包括只差大小写）时依次尝试 ` (2)`、` (3)`。远端已经存在的只差大小写的两个文件仍分别处理。分类名与文件名支持中文和空格，不能以点开头，也不能含 `..`、反斜杠或路径分隔符；「未分类」不是分类实体。图片扩展名只认 png、jpg、jpeg、gif、webp，比较时忽略扩展名大小写；手动放入的 `.jpeg` 保持原文件名，应用自己写出的 JPEG 一律用 `.jpg`。隐藏路径、临时文件、冲突副本和 `.icloud` 占位文件不导入。保留元数据目录与随机连接探测文件是存储访问校验的内部例外，不是表情路径。

同一哈希出现在多个目录时，按完整相对路径的 UTF-8 字节序选最前者；不使用操作系统排序或区域设置。其他副本不作为额外表情导入，也不随选中表情的移动、删除或彻底删除而清理。类别名称按 SQLite NOCASE 语义匹配，只折叠 ASCII，不把非 ASCII 字符转成小写。

## 每轮先拉取

先检查 manifest 和设备身份，再读日志、列举整个目录树并处理差异，最后推送本机文件动作与日志。同步仍由启动、手动操作、本机改动后 10 秒和每 5 分钟触发，不做增量列举。

本机缓存上次观察到的路径。某个哈希的远端路径与上次不同，本轮采用远端文件名与分类，放弃尚未推送的本机分类或名称改动；远端路径没变时保留本机待推送动作。日志中的旧名称不能使应用把手动改名的远端文件改回去。配文、收藏、使用次数、删除标记继续采用原来的字段时钟。

扫描先完成新增与变化路径的识别，再判断消失项。同一轮里消失路径和新增路径哈希相同，视为移动或改名，保留表情身份、配文、收藏、使用记录。新路径没有可信缓存时下载、算 SHA-256 并验证图片能解码；不凭大小认定同图。整个分类目录改名且能唯一配对时复用分类身份和颜色、排序。手建图片在解码成功后才发布原图和缩略图。

表情名称写成文件名之前，斜杠、反斜杠和控制字符替换为下划线，连续的点收成一个点，去掉开头的点和末尾空白、点。`conflict`（忽略 ASCII 大小写）改成「冲突」，「冲突副本」改成「副本」。文件名总带图片扩展名，不会以 `.icloud` 结尾，无需改写。文件名连同编号、扩展名限制在 200 个 UTF-8 字节内，截断不切开字符，清理后为空使用「表情」。目录扫描会把清理后的名称写回本机，各设备显示同一名称。手动输入名称时，空名称、斜杠、反斜杠、控制字符、开头的点和 `..` 直接报错，其余由上传清理。单张表情路径或本机原图读取失败只跳过这张表情。

## 本机路径缓存与版本

SQLite 0005 追加 `sync_path_cache`：按同步目标和路径记录大小、version、SHA-256、表情 id 和原图信息。目录缓存记录已观察目录与分类身份；未完成移动与待推送标记也只保存在本机。这些表不进入日志或快照，不创建多设备共享的可变哈希表文件。

`FileEntry.version` 来自列举响应：优先 ETag，否则用最后修改时间的字符串；文件夹使用 mtime。ETag 仅作为不透明字符串比较，不视为 MD5。S3/R2 的 ETag、WebDAV 的 getetag/getlastmodified 都直接取列举结果，不另发 stat/HEAD 请求。内存后端每次发布写入递增版本。

路径、大小、version 三项一致才跳过图片读取；任意一项变化便重新读取、计算哈希。后端既没有 ETag 也没有修改时间时，version 为 null，只比较路径和大小，**接受同大小内容替换可能漏检**，不在每次轮询重新下载。修改时间本身的精度或外部保留时间戳也会限制检测能力。

应用写入文件后发布 `file {id,path,data,version}` 操作，data 包含哈希、大小等原图信息。首次遇到路径时，若列举大小和版本与日志一致，直接用日志哈希建立缓存，并记录本次列举版本；不为计算哈希重复下载。需要在本机展示且尚无原图的接收设备仍须下载原图，并验证哈希、解码和生成缩略图。已经缓存的路径版本发生变化时，不再用旧日志跳过内容检查。路径声明记录写入确认时的版本，防止手动覆盖同一路径后，新设备误用旧声明的哈希。无版本的后端仍受上述同大小替换限制。只有路径或哈希变化时才重新发布路径声明；仅 version 不同不重发。同步文件夹经网盘复制后，各设备看到的修改时间可能不同，若按 version 重发，两台设备会每轮互相改写日志。version 对不上的设备只是多下载一次再按哈希识别。

## 移动与最近删除

Storage 保留 list/read/write/delete 四个方法，列举包含目录；以斜杠结尾的空写入创建目录（S3 为目录标记，文件夹为实际目录），read 的 NotFound 为 `Ok(None)`，delete 缺失文件成功。移动使用本机持久化意图：先记录源和目标，再写目标，用本轮结束时的目录列表确认目标大小，确认成功后才删源，最后更新缓存、清除意图。写之前使用本轮开始时的目录列表和缓存判断是否已有相同内容，不整读远端目标；写之后也不整读确认。每轮上传最多列两次根目录，路径声明和缓存更新批量写入。这里使用本机原图写入回退，不要求服务端 COPY 或 MOVE；过程中失败保留意图，下轮继续，不能先删原图；每张表情分别记录最后一次本机文件改动的 revision，分类改名也递增 revision；只有该表情的 revision 与入队时一致才清除待办，传输期间新的本机编辑仍保留。源路径若已被另一张图覆盖，不删除新内容，并撤销过时移动意图。确认送达前可能暂时同时存在两个路径，重试完成后只保留目标。

FolderStorage 仍先写同目录 `.<名字>.<随机>.tmp`，刷盘后改名；网络写入沿用 WebDAV PUT、S3 完整对象发布。日志段和原图的送达顺序彼此独立；段不完整或缺口未补齐时暂停目录投影，避免把暂时无法读取的应用日志误判为手建文件。

应用删除表情后，把文件移到 `.sticker-manager/trash/<id>.<ext>`，deleted_at 继续表示最近删除。恢复时根据原路径和仍存在的分类移回，分类已删除则写根目录。手动彻底删除或 30 天到期先发布 purge，再清理对应远端文件及本机原图；永久删除标记不清理。

用户直接删除正常目录里的文件时，在没有同哈希新路径可配对的情况下，把表情放入最近删除。本机原图仍保留，恢复可以重新上传。已观察到同哈希 trash 文件时，不把源路径消失再当作一次手动删除。历史路径声明保留恢复所需的原目录信息，而不恢复 `category_id` 字段日志。

## 字段、身份和快照

每行操作有 seq、at、device、type。HLC 取 `max(墙钟毫秒, 已见最大 at + 1)`，比较 `(at,device)`；收到尚不能应用的操作也更新已见时钟。未知操作停止该设备的后续应用，较新仓库格式要求更新应用。

- 表情身份是 UUID，哈希只用于去重。创建保留原图信息和添加时间；配文、收藏、deleted_at 独立合并，名称最终受目录路径约束。日志和创建字段里都不再出现表情 category_id，也没有分类关系操作。
- 分类实体继续记录名称、颜色、position。按名称的 ASCII NOCASE 发现重复时追加原有 merge 操作，目标为字典序较小的 id；分类引用在本机投影时跟随 alias。空分类不会因为目录为空而被删掉。
- 使用记录保留原身份、设备的累计分量，按设备取最新值，再投影相加；合并后的新增使用写入代表 id 的分量，防止重复计数。
- purge 只作用于明确列出的 id；本机发布时补齐已知合并成员。永久删除标记和 alias 都保留，迟到修改不能复活已删身份。同图重新导入生成新 UUID，不继承旧配文、关系和使用。
- 缺少原图或实体的操作进入待应用表，接收游标可以前进，后续每轮重试；presence 的接收确认停在最早未应用操作之前。完整段的应用、等待项、模型和游标同事务提交。

路径历史按原始表情 id 只保留最新正常目录路径和最新 trash 路径，以操作时钟取最大值，剪枝不依赖到达顺序。永久删除标记生效时移除该 id 的路径历史，之后到达的 File 操作也忽略，不进入快照。目录协调每轮只建立一次哈希和分类映射，先收集名称、分类分配，必要时最多投影一次，再更新分类引用；空闲轮不重写表情表。

加入或切换目标固化完整快照，保留原字段时钟、删除标记、alias、待应用项和路径声明。传输 seq 的作用域仍是 `(library id,device)`，本机 revision 独立递增；新目标从 seq 1 开始，重连旧目标在原序号后追加快照。接收投影关闭本机捕获，避免回声日志；本机分类改动只产生本机文件待办和调度通知。

## 日志段与空间清理

日志段范围补零到 12 位，内容须完整解析、连续且以换行结束；重叠部分按游标跳过，缺口后等待。本机目录出现超过本机已分配序号的段时报告设备身份冲突。已发布段不可修改，写成后本机记账失败时复用相同内容。

推送成功时在推进 pushed_seq 的同一事务清理已发布 sync_stream；outbox 只清理已经折叠且分配给当前目标的 revision。切回旧目标重新加入并追加快照，不要求保留其他目标全部历史。本机 revision 不因清理倒退。启动时仍按空页至少 256 页且占 25% 的阈值执行 checkpoint/VACUUM，运行中不全库重写。

日志段合并仍只处理本设备目录：小于 4 MiB 的源段达到 32 个时，选择连续序号，最多 128 个，累计到 4 MiB 后封段，完整纳入最后一个源段。读回并校验原字节，先写覆盖段、列举确认大小、再删源段；失败保留源段。下轮验证重叠内容后继续删除；半截覆盖段只有在源段仍完整铺满时才可删掉重建。完整但冲突的重叠内容全部保留并报错。

合并不改变 seq，不丢历史；每次 I/O 前检查许可，暂停、设置改变和网络计费限制仍生效。维护失败只写日志，不把已完成的数据同步改成失败。

## 升级边界

格式 1 不迁移。检测到根目录旧 library.json 或 format=1 时明确提示“旧同步格式，请重新创建同步仓库”，不是让用户升级应用。格式大于 2 才提示更新应用。

SQLite 只追加 0005，不修改已发布迁移。旧格式的传输队列不能发往新目标；本机内容、字段时钟、合并映射、永久删除标记仍保留，分类关联保留在本机表中。用户重新创建同步目标后从快照开始。

## 网络请求与取消

OpenDAL 0.59.5 的异步 Operator 在独立的 Tokio 运行时执行，用消息通道桥接原有阻塞 `Storage`；不嵌套 `block_on`，普通后台线程和 Tauri `spawn_blocking` 使用同一实现。所有上传下载串行，不增加并发传输。

网络请求统一使用 reqwest 0.13 的 rustls 和系统代理支持；连接超时 5 秒。普通请求的基础时限 20 秒，原图请求（png/jpg/gif/webp 路径）120 秒，发送和读响应体各按传输量另加时间（按最慢 32 KB/s 估算），大动图在慢速上行上也能传完。HTTP 429、503、其他 5xx（507 除外）及网络错误最多重试 3 次，默认退避 1、2、4 秒；有 `Retry-After` 时按秒数或 HTTP 日期等待，超过 60 秒则直接结束本轮，按正常触发规则再试。长等待和进行中的请求都每 100 毫秒检查 generation，停止或更换设置会取消，不再开始下一请求；不会等完全部重试。认证、证书错误和空间不足不重试。重试耗尽显示中文错误，下一轮沿原来的触发规则继续。

限流处理适用于所有后端，不针对任何服务写死额度。坚果云的官方说明给出的限额是免费版每 30 分钟 600 次、付费版 1500 次请求（[官方说明](https://help.jianguoyun.com/?p=2064)）；大量首次上传可能跨多轮完成。先原图后日志段，未写完日志不会记成已推送。错误只保留固定中文类别，不附带原始响应、认证头、密钥或签名 URL。

目标检查分为通用 `inspect(storage)` 和文件夹的双向包含检查。网络连接先写点开头的随机探测文件、读回比对、再删除，分别报告读、写、删除失败。非空且没有 manifest 的目标拒绝加入；已有仓库需按设备数和表情数确认。确认后重新检查目标，避免确认期间仓库被替换。

进度由 core 回调报告，回调在仓库锁外：上传报告本轮已传与总数；下载只报告本轮累计已下载的张数，因为原图随日志段分批出现，读完全部段之前不知道总数。桌面状态事件最多约每 150 毫秒更新一次，上传完成时立即更新。

## 本机凭据

settings.json 按后端保存非机密连接参数及 libraryId，兼容原有 folder 格式；未知后端仍回退默认设置。用户名、密码、Access Key ID 和 Secret Access Key 只保存在本机仓库的 `local/credentials.json`（不同步，Unix 下权限 0600）。条目以本机设备 id 加规范化目标的摘要命名。早期版本用系统钥匙串，因未签名构建每次编译都会重新弹授权框而放弃，旧条目不迁移，升级后需要重新输入一次密码。

加入快照成功后才保存凭据；保存设置失败撤销新凭据。停止同步先清除设置，再删除本机对应条目，删除失败只提示手动清理，不妨碍停止。首次需要时读凭据文件，成功或失败都缓存在进程中，重新输入凭据或停止同步时更新/清除。IPC 不返回凭据，重新输入只改凭据，换地址需先停止同步。

## 设备接收进度与表情所在设备

设备文件新增 `platform`（`"macos"` / `"windows"`；未知为空字符串）和 `received`（来源设备 ID 到已应用操作序号的映射）。`received` 的序号作用域仍是当前同步目标；存在 `sync_pending` 时取接收游标和该来源最小等待序号减一的较小值。原图未到或依赖未满足的操作不算已应用。

仓库格式为 2；设备文件的 platform 和 received 缺省时分别视为空字符串和空映射。缺少接收确认的旧设备不会被推测为已持有原图，来源设备自身仍计入。

本机 `sync_origins` 保存 `(library_id, sticker_id, device, seq)`，不使用会被投影删除的表情外键。推送分配序号、应用远端创建、重试待应用项时记录来源；加入快照中的创建以该快照的发布设备和传输序号记录。同哈希合并保留各原身份的来源，任一未彻底删除的来源被覆盖即可计入。台数为本机、来源设备、以及 received 覆盖任一来源序号的其他设备的集合大小。本机创建尚未发布时显示“等待上传”。升级前已同步的表情可能没有来源记录，显示“已同步”，不显示台数；不回放旧日志补猜来源。

`sync_device_cache` 在本机数据库缓存最近成功读取的设备列表和上次同步时间，不进入操作日志。首次加入期间不累计新表情角标，存在等待原图或依赖时继续视为首次下载；完成后仅统计新出现且未删除的远端表情哈希，排除恢复、已有同图合并和本机导入。角标本身只保存在应用内存中。
