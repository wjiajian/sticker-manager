# 用不可变日志段和字段时钟合并同步

存储后端只提供阻塞的列举（含大小）、读取、写入和删除。已实现 `std::fs` 同步文件夹，以及 OpenDAL 接入的通用 WebDAV、S3 兼容存储和 Cloudflare R2；内存测试后端可逐文件延迟送达。R2 使用 S3 协议，endpoint 为 `https://<Account ID>.r2.cloudflarestorage.com`，region 为 `auto`，不经过 WebDAV。同一 bucket 下的不同路径是不同目标。文件格式固定为版本 1，缩略图由接收设备生成。

```
<根>/
  library.json                         {"format":1,"id":"<uuid>","createdAt":毫秒}
  objects/<sha256>.<扩展名>             不可变原图
  devices/<设备 id>.json                {"id","name","lastSyncAt","platform","received"}
  ops/<设备 id>/<首 seq>-<末 seq>.jsonl  不可变日志段，序号补零到 12 位
```

设备只写自己的设备文件和日志目录，只删除自己目录中已被合并段覆盖的日志段。原图按内容哈希命名；文件夹实现先写同目录的 `.<名字>.<随机部分>.tmp`，刷盘后改名。随机部分是对固定 `.<名字>.tmp` 的调整：同一原图可能被两个设备同时上传，不能让一个写入者把另一个尚未写完的临时文件发布。读者忽略不符合正式命名的文件，包括临时文件、冲突副本和 `.icloud` 占位文件。S3/R2 在完整 PUT（或分片完成）后发布对象；WebDAV 直接 PUT，不使用临时名和 MOVE；父目录不存在（409 或 404）时才用 PROPFIND/MKCOL 建目录再写一次，平时每个文件只发一次请求。协议不要求所有后端都原子发布，由读取方的完整性校验兜底：JSONL 必须完整解析并带尾换行，原图必须通过哈希校验，半截设备 JSON 忽略，半截 `library.json` 本轮等待送达、不应用改动，也不推进上次同步时间。`library.json` 不存在则报错：仓库可能已被删除或移走，不能显示为已同步。完整但不支持的格式仍报需要更新应用。

每行操作有 `seq`、`at`、`device` 和 `type`。普通修改使用本机设备 ID；时钟取 `max(墙钟毫秒, 已见最大 at + 1)`。接收操作（包括尚不能应用的操作）时更新已见时钟。比较值统一按 `(at, device)` 字典序，设备 ID 破除同毫秒的平局。未知操作类型阻止该设备后续操作，较新的 `format` 阻止整个仓库同步，均显示“需要更新应用”。

## 值与身份

- 表情身份是 UUID，哈希只用于去重。创建带原图信息、添加时间和初始字段；`name`、`caption`、`favorite`、`deleted_at` 各自独立取新值。删除和恢复只修改 `deleted_at`；最近删除期间仍合并其他修改，重新导入等同于恢复。
- 手动彻底删除和 30 天到期都产生 `purge {ids}`。删除标记永久保留，针对这些 id 的迟到修改全部丢弃；重复 purge 无害。重新导入使用新的 UUID，不继承旧关系或使用记录。
- 删除标记只作用于列出的 id，不顺着合并扩散到同一身份的其他 id。本机删除时触发器只知道被删的那一行，同步前补上本机已知与它合并的 id，并写回待推送操作，本机和其他设备删的是同一组 id。否则，晚加入的电脑本来就有的同一张图，会因为别的设备更早的彻底删除而消失，而且结果取决于日志怎么分段。合并身份在本地用其中还活着的最小 id 表示；已删除 id 的字段、关系和使用记录不再计入。标签和分组的删除同理。
- 标签和分组的名称、颜色、所属分组、position 各自取新值（仅适用于该实体具有的字段）。删除标记永久有效。标签所指分组被删除时显示为未分组。
- 每个表情与标签对是一个有时钟的是否存在值，移除关系也保留时钟。
- 使用记录携带本设备的累计次数和最近使用时间。按设备取最新绝对值，再相加次数、取最晚时间。分配日志序号前可把一批中同一表情、同一设备的使用合为最后一条。
- 同哈希表情、按 SQLite `NOCASE` 相等的标签或分组，发现者追加 `merge {entity, from, into}`，目标是两个 ID 中字典序较小者；不能仅在内存里猜测等价关系。合并映射永久保留并可串联，之后到达的旧 ID 操作也归到目标上。字段和关系仍按原时钟比较。
- 合并前同一设备可能分别使用过两个 ID。保留原 ID 的使用计数分量，再投影为合并后每设备总数；合并后的新增使用写入代表 id 的分量。这样既不覆盖旧次数，也不把已合并总数再加一次。

## 接收、快照与本地持久化

段必须完整解析、序号连续且与文件名范围一致，最后一行须有换行；解析失败视为还没送达，不推进游标。重叠部分按已接收 seq 跳过，缺口之后暂停。若本机目录中存在大于本机已分配序号的段，停止同步并报告设备身份冲突。

缺少表情、标签、分组或原图的操作进入 SQLite 待应用表，接收游标照常前进；每次同步都重试，直到依赖到达或身份已永久删除。原图先校验 SHA-256、解码并生成缩略图，才允许创建表情。一个段的接收、待应用记录、字段状态、合并操作和游标在同一事务内提交。

0002 迁移增加同步表与事务触发器，原来的 0001 不修改。现有数据的初始时钟为 `(0, 原设备)`，真实修改总能覆盖它。本机所有数据修改自动在相同事务里追加待推送操作，未设置同步也记录；接收远端投影时关闭本地捕获，避免形成回声日志。

第一次加入或切换仓库，先固化完整快照，携带字段、关系、使用记录的原时钟，以及删除标记、合并映射和待应用项，然后追加增量。**传输 seq 的作用域是 `(library.json.id, device)`**：本地修改另有持续递增的 revision；每个目标仓库维护自己的连续传输 seq。新目标从快照 seq 1 开始，重连已有目标继续原序号并追加快照。此区分避免换仓库后产生永远补不齐的段缺口，也不必上传另一个仓库的全部历史。快照内部的值仍保留其原始设备与时间，不能被加入时间覆盖。

## 本机日志清理与空间回收

`sync_stream` 只有推送阶段读取尚未发布的行；接收进度、所在设备、身份冲突检查分别使用 `sync_progress`、`sync_origins` 和 `sync_targets.next_seq`。成功写入后，在推进 `pushed_seq` 的同一事务删除 `seq <= pushed_seq` 的行。推送失败的行保留。

`sync_outbox` 仅在操作已折叠进 `sync_model`，且当前同步目标已分配传输 seq 后删除，即 revision 不超过 model 与当前 target revision 的较小值。接收阶段 flush 后同样尝试清理，但尚未分配的增量会保留；未配置目标时只受 model revision 限制，由同一个后台调度器在无新修改 10 秒后维护。旧目标不限制清理：切换、停止后重连必须走 `join_sync`，在旧目标原序号之后追加新快照；旧目标未推送的 stream 行仍保留。删除、合并映射、待应用项仍保存在 model/pending 中。全局本地 revision 改读 `sqlite_sequence`，删光 outbox 后仍递增，UI 的变更通知不倒退。

运行中不做 VACUUM，删行留下的空页供后续写入复用。启动时，在任何窗口出现前先折叠/清理，再在空页至少 256 页且占总页数至少 25% 时执行 WAL checkpoint、VACUUM 和 checkpoint。避免周期性全库重写打断使用；首次升级回收大库也只发生在启动阶段。

## 远端日志段合并

成功完成本轮拉取与两次推送、无缺口或待应用项时，最多维护一次本机日志目录。复用本轮日志列举及新发布段，不再预先请求目录。小于 4 MiB 的源段达到 32 个时，选连续 seq 的一组，最多 128 个。累计达到 4 MiB 就停止追加，最后一个源段完整纳入，因此产物可能略超过门槛但小于 8 MiB；已达 4 MiB 的产物不再参与新的合并。这使文件数约为历史字节数 / 4 MiB + 32；很久没有新日志时，小的最后一段会保留。

内容从远端读回，使用接收端同一个 JSONL 解码器验证 UTF-8、尾换行、连续 seq、文件名首尾和发布设备，同时拒绝未知操作，核对列举大小。不依赖已删除的本地 stream；保留原始行字节和格式 1。先写 `<首>-<末>.jsonl`，再列举确认新段大小，最后逐个删除完全覆盖的源段。请求预算是 k 次读、一次写、一次列举和 k 次删除（后端重试及首次建目录可能另有请求）。任一源段读取或校验失败不写入、不删除；写失败或大小未确认不删除。

中断留下的新旧重叠段正常按游标跳过。下轮优先完成残留删除：重新读回覆盖段和残留源段，逐行比对后列举确认，再删除；每轮最多读 128 个文件，不重写覆盖段，也不同时开始另一组合并。WebDAV 可能留下写到一半的文件：覆盖段本身解析失败、而残留源段仍连续铺满它的范围时，删掉这个半截覆盖段，下轮重新合并；被完整覆盖段包含的半截源段不做比对，直接删除。格式完整但内容不同的重叠段说明序号冲突，全部保留。否则同一个半截文件会让以后每轮合并都在这里报错。列举后源段消失时，接收方本轮暂停该设备，下一轮读合并段继续；解析失败仍允许本轮尝试其他完整重叠段。合并不增加 seq，不触发本机身份冲突。

维护完全在仓库锁外，不发布 UI 进度；错误只写日志，不改变已同步状态。每次维护 I/O 前检查许可：暂停或设置改变立即停止；网络后端在计费网络上始终不合并，关闭自动暂停选项或手动立即同步也不能绕过。同步文件夹仍可合并。已开始的请求沿已有 generation 取消机制处理。

## 传输与后台

先上传待推送操作引用的原图，再发布日志段，再记已推送进度；中断重试无害。每轮还补传当前表情（含最近删除）缺失或远端大小不完整的原图，避免其他设备清理旧身份的原图后，新身份无法下载。彻底删除的原图在 purge 日志发布后清理。日志段可按上面“远端日志段合并”的规则合并，不丢弃历史。

目录列举、原图传输、哈希校验和缩略图生成都在仓库 Mutex 外进行；锁只用于取任务及提交数据库。单后台工作线程处理启动、手动、10 秒无新修改和每 5 分钟触发，运行中再次触发则追加一次。每秒采样墙钟，超过 15 秒的间隔视为睡眠唤醒。切换设置先取消旧任务并等其当前阶段结束，再取新快照。


## 网络请求与取消

OpenDAL 0.59.5 的异步 Operator 在独立的 Tokio 运行时执行，用消息通道桥接原有阻塞 `Storage`；不嵌套 `block_on`，普通后台线程和 Tauri `spawn_blocking` 使用同一实现。所有上传下载串行，不增加并发传输。

网络请求统一使用 reqwest 0.13 的 rustls 和系统代理支持；连接超时 5 秒。普通请求的基础时限 20 秒，原图请求 120 秒，发送和读响应体各按传输量另加时间（按最慢 32 KB/s 估算），大动图在慢速上行上也能传完。HTTP 429、503、其他 5xx（507 除外）及网络错误最多重试 3 次，默认退避 1、2、4 秒；有 `Retry-After` 时按秒数或 HTTP 日期等待，超过 60 秒则直接结束本轮，按正常触发规则再试。长等待和进行中的请求都每 100 毫秒检查 generation，停止或更换设置会取消，不再开始下一请求；不会等完全部重试。认证、证书错误和空间不足不重试。重试耗尽显示中文错误，下一轮沿原来的触发规则继续。

限流处理适用于所有后端，不针对任何服务写死额度。坚果云的官方说明给出的限额是免费版每 30 分钟 600 次、付费版 1500 次请求（[官方说明](https://help.jianguoyun.com/?p=2064)）；大量首次上传可能跨多轮完成。先原图后日志段，未写完日志不会记成已推送。错误只保留固定中文类别，不附带原始响应、认证头、密钥或签名 URL。

目标检查分为通用 `inspect(storage)` 和文件夹的双向包含检查。网络连接先写点开头的随机探测文件、读回比对、再删除，分别报告读、写、删除失败。非空且没有 manifest 的目标拒绝加入；已有仓库需按设备数和表情数确认。确认后重新检查目标，避免确认期间仓库被替换。

进度由 core 回调报告，回调在仓库锁外：上传报告本轮已传与总数；下载只报告本轮累计已下载的张数，因为原图随日志段分批出现，读完全部段之前不知道总数。桌面状态事件最多约每 150 毫秒更新一次，上传完成时立即更新。

## 本机凭据

settings.json 按后端保存非机密连接参数及 libraryId，兼容原有 folder 格式；未知后端仍回退默认设置。用户名、密码、Access Key ID 和 Secret Access Key 只保存在系统钥匙串，通过 keyring 4.2.0 的 v1 接口使用 macOS 钥匙串和 Windows 凭据管理器。条目以本机设备 id 加规范化目标的摘要命名，调试版与发布版的 service 名不同。

加入快照成功后才保存凭据；保存设置失败撤销新凭据。停止同步先清除设置，再删除本机对应条目，删除失败只提示手动清理，不妨碍停止。首次需要时读钥匙串，成功或失败都缓存在进程中，重新输入凭据或停止同步时更新/清除，避免未签名调试程序周期性弹权限框。IPC 不返回凭据，重新输入只改凭据，换地址需先停止同步。

## 设备接收进度与表情所在设备

设备文件新增 `platform`（`"macos"` / `"windows"`；未知为空字符串）和 `received`（来源设备 ID 到已应用操作序号的映射）。`received` 的序号作用域仍是当前同步目标；存在 `sync_pending` 时取接收游标和该来源最小等待序号减一的较小值。原图未到或依赖未满足的操作不算已应用。

文件格式仍为 1：旧版本忽略新增字段；新版本读取旧设备文件时将 platform 和 received 分别视为空字符串和空映射。缺少接收确认的旧设备不会被推测为已持有原图，来源设备自身仍计入。

本机 `sync_origins` 保存 `(library_id, sticker_id, device, seq)`，不使用会被投影删除的表情外键。推送分配序号、应用远端创建、重试待应用项时记录来源；加入快照中的创建以该快照的发布设备和传输序号记录。同哈希合并保留各原身份的来源，任一未彻底删除的来源被覆盖即可计入。台数为本机、来源设备、以及 received 覆盖任一来源序号的其他设备的集合大小。本机创建尚未发布时显示“等待上传”。升级前已同步的表情可能没有来源记录，显示“已同步”，不显示台数；不回放旧日志补猜来源。

`sync_device_cache` 在本机数据库缓存最近成功读取的设备列表和上次同步时间，不进入操作日志。首次加入期间不累计新表情角标，存在等待原图或依赖时继续视为首次下载；完成后仅统计新出现且未删除的远端表情哈希，排除恢复、已有同图合并和本机导入。角标本身只保存在应用内存中。
