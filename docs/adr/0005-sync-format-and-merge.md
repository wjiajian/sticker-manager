# 用不可变日志段和字段时钟合并同步

存储后端只提供阻塞的列举（含大小）、读取、原子写入和删除。第一种实现是 `std::fs` 同步文件夹，测试后端可逐文件延迟送达；WebDAV、S3 兼容和 R2 以后实现同一个接口。文件格式固定为版本 1，缩略图由接收设备生成。

```
<根>/
  library.json                         {"format":1,"id":"<uuid>","createdAt":毫秒}
  objects/<sha256>.<扩展名>             不可变原图
  devices/<设备 id>.json                {"id","name","lastSyncAt"}
  ops/<设备 id>/<首 seq>-<末 seq>.jsonl  不可变日志段，序号补零到 12 位
```

设备只写自己的设备文件和日志目录。原图按内容哈希命名；文件夹实现先写同目录的 `.<名字>.<随机部分>.tmp`，刷盘后改名。随机部分是对固定 `.<名字>.tmp` 的调整：同一原图可能被两个设备同时上传，不能让一个写入者把另一个尚未写完的临时文件发布。读者忽略不符合正式命名的文件，包括临时文件、冲突副本和 `.icloud` 占位文件。

每行操作有 `seq`、`at`、`device` 和 `type`。普通修改使用本机设备 ID；时钟取 `max(墙钟毫秒, 已见最大 at + 1)`。接收操作（包括尚不能应用的操作）时更新已见时钟。比较值统一按 `(at, device)` 字典序，设备 ID 破除同毫秒的平局。未知操作类型阻止该设备后续操作，较新的 `format` 阻止整个仓库同步，均显示“需要更新应用”。

## 值与身份

- 表情身份是 UUID，哈希只用于去重。创建带原图信息、添加时间和初始字段；`name`、`caption`、`favorite`、`deleted_at` 各自独立取新值。删除和恢复只修改 `deleted_at`；最近删除期间仍合并其他修改，重新导入等同于恢复。
- 手动彻底删除和 30 天到期都产生 `purge {ids}`。删除标记永久保留，针对这些 id 的迟到修改全部丢弃；重复 purge 无害。重新导入使用新的 UUID，不继承旧关系或使用记录。
- 删除标记只作用于列出的 id，不顺着合并扩散到同一身份的其他 id。本机删除时触发器只知道被删的那一行，同步前补上本机已知与它合并的 id，并写回待推送操作，本机和其他设备删的是同一组 id。否则，晚加入的电脑本来就有的同一张图，会因为别的设备更早的彻底删除而消失，而且结果取决于日志怎么分段。合并身份在本地用其中还活着的最小 id 表示；已删除 id 的字段、关系和使用记录不再计入。标签和分组的删除同理。
- 标签和分组的名称、颜色、所属分组、position 各自取新值（仅适用于该实体具有的字段）。删除标记永久有效。标签所指分组被删除时显示为未分组。
- 每个表情与标签对是一个有时钟的是否存在值，移除关系也保留时钟。
- 使用记录携带本设备的累计次数和最近使用时间。按设备取最新绝对值，再相加次数、取最晚时间。分配日志序号前可把一批中同一表情、同一设备的使用合为最后一条。
- 同哈希表情、按 SQLite `NOCASE` 相等的标签或分组，发现者追加 `merge {entity, from, into}`，目标是两个 ID 中字典序较小者；不能仅在内存里猜测等价关系。合并映射永久保留并可串联，之后到达的旧 ID 操作也归到目标上。字段和关系仍按原时钟比较。
- 合并前同一设备可能分别使用过两个 ID。保留原 ID 的使用计数分量，再投影为合并后每设备总数；合并后的新增使用写入代表 id 的分量。这样既不覆盖旧次数，也不把已合并总数再加一次。

## 接收、快照与本地持久化

段必须完整解析、序号连续且与文件名范围一致，最后一行须有换行；解析失败视为还没送达，不推进游标。重叠部分按已接收 seq 跳过，缺口之后暂停。若本机目录中存在大于本机已分配序号的段，停止同步并报告设备身份冲突。

缺少表情、标签、分组或原图的操作进入 SQLite 待应用表，接收游标照常前进；每次同步都重试，直到依赖到达或身份已永久删除。原图先校验 SHA-256、解码并生成缩略图，才允许创建表情。一个段的接收、待应用记录、字段状态、合并操作和游标在同一事务内提交。

0002 迁移增加同步表与事务触发器，原来的 0001 不修改。现有数据的初始时钟为 `(0, 原设备)`，真实修改总能覆盖它。本机所有数据修改自动在相同事务里追加待推送操作，未设置同步也记录；接收远端投影时关闭本地捕获，避免形成回声日志。

第一次加入或切换仓库，先固化完整快照，携带字段、关系、使用记录的原时钟，以及删除标记、合并映射和待应用项，然后追加增量。**传输 seq 的作用域是 `(library.json.id, device)`**：本地修改另有持续递增的 revision；每个目标仓库维护自己的连续传输 seq。新目标从快照 seq 1 开始，重连已有目标继续原序号并追加快照。此区分避免换仓库后产生永远补不齐的段缺口，也不必上传另一个仓库的全部历史。快照内部的值仍保留其原始设备与时间，不能被加入时间覆盖。

## 传输与后台

先上传待推送操作引用的原图，再发布日志段，再记已推送进度；中断重试无害。每轮还补传当前表情（含最近删除）缺失的原图，避免其他设备清理旧身份的原图后，新身份无法下载。彻底删除的原图在 purge 日志发布后清理，日志段本轮只增不减，不压缩、不回收。

目录列举、原图传输、哈希校验和缩略图生成都在仓库 Mutex 外进行；锁只用于取任务及提交数据库。单后台工作线程处理启动、手动、10 秒无新修改和每 5 分钟触发，运行中再次触发则追加一次。每秒采样墙钟，超过 15 秒的间隔视为睡眠唤醒。切换设置先取消旧任务并等其当前阶段结束，再取新快照。
