# 剪贴板格式实测记录

> 历史记录：代理交回的实测结论，对应剪贴板改为只写文件 URL 的提交。完整矩阵只在代理回复里给过，没有存档；现状以 [docs/tech-stack.md](../tech-stack.md) 的“剪贴板”一节为准。

日期：2026-11-03，macOS 27.0.1。测试图为透明 PNG、JPG、四帧 GIF、静态 WebP、四帧 WebP；组合为文件 URL + PNG（原来的“复制”）、只有 PNG、只有文件 URL、GIF 原始数据 + PNG、GIF 原始数据 + PNG + 文件 URL。只粘进自己会话的输入框，没有发送，没有做拖拽测试，测试后恢复了剪贴板。

QQ 6.9.98、飞书 7.74.21：五种图在文件 URL + PNG、PNG-only、文件 URL-only 三种组合下，在 QQ 普通自聊和飞书都能粘成图片缩略图；GIF 的原始数据 + PNG（有无文件 URL）也能粘成图片。飞书带文件 URL 时引用原 GIF，只有 GIF 数据 + PNG 时仍取静态图片，故不增加 GIF 剪贴板类型。QQ“我的手机”对所有组合都显示文件确认框，连 PNG-only 也如此，不能把该会话的文件卡片归因于文件 URL。

QQ 普通自聊中透明 PNG 的洞和外围透出输入框浅灰背景；飞书白色背景下未见黑块，但尚不能区分透明与白色填充。微信 4.2.0 在登录后的文件传输助手中补测了同样 17 个组合：后台 ⌘V 均能插入附件占位并启用发送按钮，清空后恢复禁用；后台菜单曾把 PNG-only 的粘贴显示为禁用。用户将微信放到前台后，工具截图仍无法辨认图片；其中 PNG-only 的透明 PNG 已由用户目视确认为图片缩略图，其余组合外观及透明度未核实。所有测试均未发送，微信剩余外观、飞书透明度和动画发送后是否保留仍待[人工验收](../../TODO.md)。

最终按“优先保障聊天软件复制粘贴”的取舍选择文件 URL-only：QQ 普通自聊、飞书中与 PNG + 文件 URL 一样能粘成图片，没有验证出混合格式的额外收益；统一交出原文件，避免让目标应用在原文件和静态首帧之间选择。[此前旧应用实测](2026-11-02-appearance-purge-compaction.md#剪贴板探索)中，文件 URL-only 在 Chrome、备忘录可插入，在 Safari、文本编辑无反应；接受这项兼容性取舍，本轮不重测旧应用。不按前台应用分流。
